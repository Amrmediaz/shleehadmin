# Shleeh Owner (شاليه.كوم — Owner)

Flutter app for chalet owners on Shleeh. Built with `flutter_bloc` (Cubit).

## What's in this build

Bottom-nav app with 3 tabs after login:

- **Dashboard** — `GET /AppOwner/HomePage`: customers, chalets, hotel buildings, building owners, bookings, hotel bookings, revenue, hotel revenue.
- **Bookings** — "Paid" / "Not Paid" sub-tabs (`POST /AppOwner/PaidBookingList`, `POST /AppOwner/NotPaidBookingList`), paginated. Tapping a booking opens its details (`GET /AppOwner/BookingDetiles?ID=`), showing the customer, chalet, booked days, and — for unpaid bookings — an **Enable Payment** button that opens a sheet calling `POST /AppOwner/OutPayment`.
- **Payments** — `POST /AppOwner/PaymentList`, paginated transaction history.
- **Login** — `POST /AppOwner/AppOwnerLogin`, token stored locally; auto-login on relaunch; automatic redirect to login on any `401`.
- **Arabic / English** — full UI is localized (Arabic default, RTL). Tap the language pill in the app bar (login screen and after login) to switch; the choice is remembered across restarts.

## One-time setup (run locally — this project was scaffolded without the Flutter SDK)

This repo only contains the Dart source (`lib/`), `pubspec.yaml`, and config — no `android/`/`ios`/`web` folders yet. From a machine with Flutter installed:

```bash
cd shleeh_owner
flutter create . --org com.shleeh --project-name shleeh_owner
flutter pub get
flutter run
```

`flutter create .` on a folder that already has a `pubspec.yaml` only fills in the missing platform folders — it won't touch `lib/`. After running it, double-check `pubspec.yaml` still has the dependencies listed below; if it got reset, re-add them and run `flutter pub get` again.

**Localization note:** `lib/l10n/generated/app_localizations.dart` (the `AppLocalizations` class code references) doesn't exist in this repo — it's auto-generated by `flutter pub get` because `generate: true` is set in `pubspec.yaml` and `flutter_localizations` is a dependency. The app will not compile until you've run `flutter pub get` at least once locally. If you ever see "target of URI doesn't exist: 'generated/app_localizations.dart'", that just means `pub get` hasn't run yet.

## Localization

- Source strings live in `lib/l10n/app_en.arb` (template, with placeholder metadata) and `lib/l10n/app_ar.arb` (Arabic translations). Add a new key to both files, then re-run `flutter pub get` (or `flutter gen-l10n`) to regenerate `AppLocalizations`.
- In widgets, use `context.l10n.yourKey` (the `context.l10n` shortcut is defined in `lib/l10n/l10n_extensions.dart`) rather than importing the generated class directly.
- Default locale is Arabic; `lib/core/locale/locale_cubit.dart` persists the owner's chosen locale via `shared_preferences`. RTL is automatic — Flutter switches `Directionality` based on the active locale, no extra layout work was needed.
- **Scope note:** only user-facing widget text is localized. Low-level fallback error strings thrown from `ApiClient`/`ApiException` and the generic cubit catch-blocks ("Could not reach the server…") are still English — they live outside `BuildContext`, so localizing them would need either passing `BuildContext` into the data/business layer (an anti-pattern) or a context-free locale lookup. Flag if you want these translated too and I'll wire up a proper solution (e.g. error codes translated at the UI layer).

## Project structure

```
lib/
  core/
    network/        # ApiClient (query params, {status,message} envelope unwrap), endpoint constants, ApiException
    storage/         # SessionStorage (token persistence via shared_preferences)
    models/          # PaginatedResult<T> (shared pagination shape)
    locale/           # LocaleCubit (current Locale, persisted, defaults to Arabic)
    widgets/         # StatCard, StatusChip, LoadingView, ErrorView, EmptyView, PaginationFooter, LanguageToggleButton
  l10n/
    app_en.arb        # template strings (English) + placeholder metadata
    app_ar.arb         # Arabic translations
    l10n_extensions.dart  # context.l10n shortcut
    generated/          # auto-generated by `flutter pub get` — not checked in by hand
  features/
    auth/            # login screen + AuthCubit + AuthRepository
    dashboard/       # HomePage stats screen + HomeCubit + HomeRepository
    bookings/        # Booking/BookingBuilding/BookingCustomer/BookingDay models,
                      # BookingsRepository, list + details cubits/screens
    payment/          # PaymentListItem model + PaymentRepository (list + OutPayment),
                      # payment list screen, enable-payment bottom sheet, PaymentCubit
  app/
    app.dart          # MaterialApp, auth-gated routing, locale wiring
    app_shell.dart     # Bottom-nav shell (Dashboard / Bookings / Payments)
  main.dart
```

## Notes / assumptions to confirm with the backend

- The login response field is spelled `expaire` (not `expires`) — handled as-is in `OwnerSession`.
- Most AppOwner endpoints wrap their payload as `{"status": bool, "message": ...}`. `ApiClient.getEnvelope`/`postEnvelope` unwrap this and throw if `status` is false.
- **All three list endpoints (`PaidBookingList`, `NotPaidBookingList`, `PaymentList`) are `POST`** with a `{"page": int, "pageSize": int}` request body (both confirmed via swagger).
- The swagger's example payload shows `"page": 0` — if the server treats `page` as 0-indexed (0 = first page) rather than 1-indexed, `BookingsRepository`/`PaymentRepository` currently sending `page: 1` for the first screen would actually request the *second* page. If the first list screen looks like it's skipping page 1, change the `page:` default/params in those repositories from 1-indexed to `page - 1` (0-indexed) when calling the API.
- `paymenttype` (OutPayment / PaymentList) and `bookingstatus` (bookings) aren't documented beyond the example values seen in real data (`paymenttype`: 1 or 2, `bookingstatus`: 0 or 1). The app currently infers `bookingstatus == 1` means "paid" — this matched the sample data but should be confirmed. See `PaymentType` in `lib/features/payment/data/payment_repository.dart` and `Booking.isPaid` in `lib/features/bookings/data/booking.dart`.
- Base URL is hardcoded to `https://shleeh.com/api` in `lib/core/network/api_endpoints.dart`.
